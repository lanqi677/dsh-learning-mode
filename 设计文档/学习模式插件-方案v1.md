## 1. 架构：三层，各自职责单一

```
┌─ 客户端层（浏览器侧插件，React 组件）
│   右侧 Details 面板：渲染树 + 每节点 [✓学会] [🎯聚焦] 按钮
│   会话级开关：未开启 → render null（什么都不出现）
│
├─ 宿主层（node 侧插件）
│   ① 工具：outline_show / add / update / done / focus
│   ② agent/pre-step 注入：焦点路径 + 摘要 + 待办
│   ③ 会话开关判定（闸门）
│   ④ 摘要管道：用 ctx.llm 生成节点摘要（异步）
│
└─ 数据层
    outline.json  —— 长期资产（跨会话）
    sessions.json —— 每会话的开关/焦点（轻量）
```

已核实的 DSH 现成接缝（本机安装包 .d.ts 实测，非推测）：

| 能力 | 接缝 |
|---|---|

| 悬浮层 | `shell.overlay`（list slot，additive、默认点击穿透） |
| 工具定义 | `defineTool`（@deepseek-ai/dsh-tools） |

| UI 卸载级联 | slot `register` 走 `ctx.effect`，插件卸载自动清理 |

## 2. 零侵入方案（对应要求 5）★

三道闸门，**默认全关**：

### 闸门 1：工具 —— 用 Agent 预设隔离（首选）

把插件行写进**"学习模式"预设**的 `agent.cordis.yml`。DSH 原生支持"插件在 agent 作用域激活"，于是：

- 学习模式预设的会话：5 个工具在 schema 里；
- **其它所有会话：工具 schema 一个字节都不变**（连"存在但拒绝调用"都没有）。

这比"全局注册 + 运行时守卫"更干净——后者会让每个会话的工具列表多 5 项，污染上下文与缓存前缀。

> 退路：若要支持"中途开启"，就用全局注册 + 会话守卫。代价是 5 个工具常驻所有会话的 schema。

### 闸门 2：注入 —— pre-step 首行判开关

```js
ctx.on("agent/pre-step", ({ agent, messages }, next) => {
  try {
    if (!state.isEnabled(agent.id)) return next();   // 未开启：零开销返回
    ...                                              // 开启：构造注入段
  } catch (e) { safeLog(e); }                        // 绝不冒泡到主流程
  return next();
});
```

### 闸门 3：UI —— 未开启时 render null

面板组件订阅会话级开关，未开启直接返回 `null`，**不占位、不显示 tab**。开启入口见 §3。

### 兜底原则（DSH 有过"装完插件 harness 直接不可用"的真实事故）

- 所有事件回调、工具、摘要任务：**全部 try/catch**，失败只记日志；
- 注入构造失败 → 静默跳过本轮注入，不改 messages；
- 摘要生成失败 → 标记 `pending`，不阻塞任何交互；
- 数据文件损坏 → 备份后重建空树，不抛异常。

## 3. 开启方式：两种，建议组合

| 方式 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 新会话选预设**（主） | 新建会话时选"学习模式"预设 | 隔离最干净（工具都不存在）；从第一轮就是学习语境 | 想中途开启要多一步 |
| **B. 面板按钮**（兜底） | 右侧面板 tab 里一个"开启学习模式"按钮，写会话级开关 | 随机应变 | 工具得全局注册（见闸门 1 退路） |

**建议**：A 为主。你说的"新开页面时存在按钮"——最贴合的落点是**新建会话界面的"学习模式"入口**（预设在 DSH 里本来就是会话创建属性），而不是在已有会话里塞按钮。

## 4. 数据模型

### 4.1 一个关键决策：树是全局资产，会话只是"当前视图"

今天学 Java、明天继续学——树必须跨会话存活：

```jsonc
// outline.json —— 长期资产，与会话无关
{
  "projects": {
    "java": { "title": "Java", "roots": ["java.obj", "java.mem", "java.syntax"] }
  },
  "nodes": {
    "java.obj": { "title": "对象", "parent": "java", "project": "java", "order": 0,
                  "status": "doing" },
    "java.obj.inherit": { "title": "继承", "parent": "java.obj", "order": 0, "status": "todo" },
    "java.obj.oop": { "title": "面向对象思想", "parent": "java.obj", "order": 2,
                      "status": "done", "doneAt": "2026-09-17T10:00:00Z",
                      "note": "封装/继承/多态三者关系；多态靠动态绑定；易错：重载≠重写",
                      "noteAt": "2026-09-17T10:00:05Z",
                      "noteSource": { "sessionId": "s-1", "from": 42, "to": 57 } }
  }
}
```

- **扁平节点 + parent 指针**（不是嵌套 JSON）：改名/移位/删除都简单，树形只是渲染结果。
- **`status`**：`todo` / `doing` / `done`。"划掉"是 `done` 的渲染，"是否显示已完成"是**视图开关**，不是数据。
- **`note` + `noteAt` + `noteSource`**：摘要本体 + 生成时间 + 溯源窗口（日后可加"查看当时会话"）。

### 4.2 会话状态（轻量）

```jsonc
// sessions.json
{ "s-1": { "enabled": true, "project": "java", "focus": "java.obj.oop",
           "focusSince": "2026-09-17T09:50:00Z", "cursor": 42 } }
```

`cursor` = 该节点开始聚焦时的会话消息序号，**这是摘要管道的原料区间起点**。

## 5. 交互面（对应要求 1、4）

### 5.1 面板（右侧 Details）

```
▼ Java                        项目
  ▼ 对象                      [✓ 学会] [🎯 聚焦中]
      ├ 继承                   [✓ 学会] [🎯 聚焦]
      ├ 私有                   [✓ 学会] [🎯 聚焦]
      └ 面向对象思想  ~~~       [✓ 已完成] [🎯 聚焦]   ← hover 显示摘要卡片
  ▼ 内存管理                   [✓ 学会] [🎯 聚焦]
  ▶ 语法                       [✓ 学会] [🎯 聚焦]
  已完成 3/9        [显示已完成 ✓]  [＋新项目]  [⋯]
```

| 操作 | 行为 |
|---|---|
| 点节点标题 | **聚焦**（等价于 AI 调 `outline_focus`）；同时触发"离开旧节点"的摘要检查 |
| **[✓ 学会]** | 标记 `done` + **触发摘要生成**（要求 2）；可再次点击撤销 |
| **[🎯 聚焦]** | 同上，给不想点标题的人 |
| **[显示已完成]** | 纯视图开关，只影响渲染 |
| **⋯** | 关闭学习模式（当前会话）/ 打开数据文件 |
| **hover 节点** | 展示摘要（要求 2 的"跳过去看学习记录"） |

**不做 UI 拖拽编辑**（要求 4）：改结构靠跟 AI 说 → AI 调 `outline_update`。省掉一整个编辑器，值。

### 5.2 两条状态变更入口，汇到一处

```
人手点击  ──┐
            ├──▶  OutlineStore.apply(op)  ──▶  写 outline.json  ──▶  广播给面板 & 注入层
AI 调工具 ──┘
```

**同一份状态、同一个变更函数**。否则会出现"人手改了 AI 不知道 / AI 改了面板不刷新"的经典撕裂。

## 6. 摘要管道（对应要求 2）★ 最容易做错的一环

### 6.1 触发时机（你指定的两个）

| 触发 | 条件 | 备注 |
|---|---|---|
| 点 **[✓ 学会]** | 该节点有实质对话内容 | 完成即沉淀 |
| **焦点切换**（点别的节点 / AI 聚焦别处 / 会话结束） | 旧节点停留期间 **≥ 4 条消息 或 ≥ 200 字** | 门槛防"空摘要"和烧钱 |

### 6.2 由谁生成：**插件自己调 LLM，不走 Agent 对话**

若走 Agent 对话（往会话塞一条"请总结"的消息），会污染聊天记录、占用一轮对话、可能打断你当前思路。

改为：插件用 `ctx.llm` 直接调一次轻量模型，输入：

```
[节点路径] Java > 对象 > 面向对象思想
[已有摘要] （若有：增量更新而非重写）
[聚焦期间的对话片段] 从 sessions.json 的 cursor 到当前，截断到 ~3000 token
[输出要求] 2-4 句：核心结论 / 易错点 / 待续问题。禁止复述对话，禁止空话。
```

输出直接写 `node.note`。**全程异步、不阻塞 UI、不打断对话、不进聊天记录。**

### 6.3 失败与成本

- 失败 → 标 `noteState: "pending"`，下次切换重试（最多 3 次）；
- 成本控制 → 门槛 + 单次输出上限 + 同一节点 5 分钟内不重复生成；
- **摘要 ≠ 聊天记录**：它自包含，所以将来复习不需要翻历史——这正是你要的东西。

## 7. 上下文注入（对应要求 3）

每轮注入一个小块，**硬上限约 400 token**：

```markdown
## 学习模式（当前会话已开启）
项目：Java ｜ 焦点：Java > 对象 > 面向对象思想

【当前节点摘要】封装/继承/多态三者关系；多态靠动态绑定；易错：重载≠重写
【子节点摘要】
  · 继承：…（有摘要才列）
  · 私有：…（有摘要才列）
【未完成（1-2 级，按序）】内存管理、语法、继承
【最近完成】对象 > 面向对象思想（09-17）、数组（09-16）
```

规则：

1. **有摘要的节点，摘要必进上下文**（要求 3）——当前节点 + 其子节点；
2. 父链只给**标题**，不给摘要（防向上膨胀）；
3. 未完成项截断到 N 条（默认 8），最近完成截断到 3 条；
4. **整棵树只在 AI 调 `outline_show` 时提供**，绝不每轮注入；
5. 未开启学习模式的会话：**一行都不注入**。

## 8. 工具面（5 个）

| 工具 | 谁调 | 说明 |
|---|---|---|
| `outline_show(path?, includeDone?)` | AI | 读树；**建树前必须先调，用于查重** |
| `outline_add(parentPath, items[])` | AI | 追加子项；**幂等**：同名兄弟已存在 → 跳过并回报"已存在" |
| `outline_update(node, rename?/move?/delete?)` | AI | 改名 / 移位 / 删除（要求 4 的人审修改方式） |
| `outline_done(node, note?, undo?)` | AI | 与面板 ✓ 按钮**走同一函数** |
| `outline_focus(node)` | AI | 聚焦；与面板点标题走同一函数 |

寻址策略：**AI 传名字路径**（`Java/对象`）→ 插件解析成 id；**歧义时报错并要求澄清**，不猜。

（WeSmartFlow 的 `create_quiz` 在同类问题上踩过"模型臆造 id"的坑，它的处理是"返回结构化错误让 AI 自行修正、不抛异常中断对话"——照抄。）

## 9. 提示词规则（插件注入，不是可选）

1. 用户问"X 要学什么 / 包含什么" → **先 `outline_show` 查重 → `outline_add` 只补缺失项** → 用 1-2 句说明，**不要复述整棵树**。
2. 用户说"学完了 / 懂了" → `outline_done`（AI 自己判断的必须先问一句再标）。
3. 用户要调整结构 → `outline_update`，**不要重建**已有节点。
4. **不要为了"整齐"重构已有树**——粒度不齐是正常的，由人来审（要求 4）。
5. 聊天里只打**增量**（"已在 对象 下添加：继承、私有"），不打整棵树。

## 11. 验收清单：怎么证明"零侵入"（要求 5）

- [ ] 新建**普通**会话：面板 tab 不出现、工具列表无变化、每轮 messages 无注入（看会话日志）
- [ ] 新建**学习模式**会话：面板出现、工具可用、注入正确
- [ ] 同一会话内**关闭**学习模式：立即恢复无注入、无面板，且不影响正在进行的对话
- [ ] **卸载插件**：面板消失、无残留（slot 走 ctx.effect 自动级联）
- [ ] **异常演练**：手动让注入抛错 → agent 仍能正常回话；让摘要失败 → 面板不卡、不报错
- [ ] 数据文件写坏 → 备份重建，不崩

## 12. 待验证的 3 个技术点（先做 spike，别闷头写）

1. **摘要原料从哪来** ★ 最关键：插件能否读到会话的消息/事件日志（`ctx.sessions` 或 session-controller 的事件读取）。这决定摘要管道的实现方式，第一天就要验。
2. **客户端面板的构建链路**：客户端插件需要构建产物或 web dev server 才能热更新；要先确认最快的开发-验证闭环。
3. **焦点切换触发的频率控制**：防止"来回点几下就调 10 次 LLM"。
