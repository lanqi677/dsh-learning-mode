
## 3. ★ 启动时序与就绪性（回答"能不能立刻启动"）

分三层，结论不同，都有依据。

### 3.1 宿主层（工具 + 注入）：**有框架级保证，不会晚**

框架契约原文（`dsh-agent-presets/mount`）：

> "Mount one preset composition under an agent's scope context, then **prove the result is usable before the agent is published**."

以及预设组合的形态：

> "The roster mounts it **ONCE** under a standing scope; every session naming it **joins by scope parentage**, so the tools and prompt sections registered here cover each joined agent while a session's own state stays keyed per Session/Agent inside the plugins."

三条推论，都是**设计约束**，不是可选优化：

1. **不存在"第一轮工具还没到"的竞态** —— 工具与 `pre-step` 监听器在**会话发布之前**就已注册。
2. **多个学习会话共享同一个 standing mount** —— 插件内部状态必须**按 agent/session 分键**，否则两个学习会话会互相串味（比如焦点互相覆盖）。
3. **mount 失败 = 该预设无法创建会话** —— 契约里还有一句："A row that never reached a usable state is rejected"。所以插件的挂载路径必须做到 **零 I/O、零外部依赖**：
   - ✅ 挂载时只做：注册工具、注册监听器、注册 slot 描述
   - ❌ 挂载时不要：读磁盘、建连接、调 LLM、解析大文件
   - 所有重活 = **首次使用时懒加载 + await**。

   > 否则一个 bug 的后果是"**学习模式彻底开不了会话**"。虽然不影响其它预设（普通会话照常），但这是最痛的失败模式，必须靠"挂载期零风险"来规避。

4. **作用域即闸门**：scope 过滤派发意味着"agent 作用域的监听器只收到该 agent 的事件"——我的注入**天生只对学习会话生效**，不需要手写 `isEnabled` 判断。（仍保留一行断言做双保险。）

### 3.2 客户端层（面板）：**没有框架级保证，会晚一点**

实测：预设是 **agent 平面**。本机 `router/agent.cordis.yml`（265 行）里全部是 persona / agent-instructions / tools / planning / compaction / delegation 之类的 agent 行，**没有 client 行**；而且它明确写了"A service row here MUST sit inside a group carrying an `isolate` realm"，整个文件的关注点是 agent 作用域。

→ 所以浏览器插件**无法随预设做作用域隔离**，只能**全局注册 + 按会话条件渲染**。

| 影响 | 对策 |
|---|---|
| 面板可能比首轮晚 1–2 秒出现（客户端插件异步加载 + 会话握手） | 面板先渲染骨架屏；**首轮绑定流程不依赖面板存在** |
| UI 代码常驻所有会话 | 未开启学习模式的会话 `render null`——**代码常驻，行为零侵入** |
| 需要判断"当前会话是不是学习会话" | 通过会话投影读 preset（本机存在 `dsh-client-ui-agent-preset` 包，说明这条路通；实现时确认字段名） |

**这是本方案对"零侵入"的唯一让步，必须如实记录**：宿主侧是严格隔离的，UI 侧是条件渲染。

### 3.3 数据层：**需要自己保证**

数据异步加载，**未就绪时的行为必须三类分开定义**，否则会出现"第一轮问 AI 学习进度，AI 说没有"这种最伤信任的 bug：

| 场景 | 未就绪时的正确行为 |
|---|---|
| 注入 | **跳过注入**（绝不注入空块/占位符误导模型） |
| 面板 | 骨架屏 |
| 工具被调用 | **await 首次加载完成**再执行，而不是返回"暂无数据" |

### 3.4 另外三个时序问题（都已验证）

| 情况 | 行为 |
|---|---|
| **恢复旧会话**（resume） | 预设身份随会话持久化（`ensureSession(..., presetId)`）→ 仍在学习模式里，组件自然重挂；绑定关系存在 `sessions.json`，**不会重新问选树** |
| **中途换预设** | 框架拒绝（错误码："Explicit-id creation attempted to adopt a Session under another preset"）→ 与"只留预设入口"的决定一致，也避免了半开状态 |
| **两个学习会话同时开** | 共享 standing mount → 状态按 agent 分键；写树文件要**串行化**（同进程一个写队列），避免并发写坏 |

## 4. 零侵入（更新版）

| 层 | 隔离方式 | 强度 |
|---|---|---|
| 工具 | **随预设作用域**，其它会话的工具 schema 完全不含它们 | 强（框架保证） |
| 注入 | **随作用域派发**，天生只对学习会话生效 | 强（框架保证） |
| UI | 全局注册 + 会话条件渲染 null | 中（代码常驻，行为零侵入） |
| 异常 | 全链路 try/catch：注入失败静默跳过、摘要失败标 pending 重试、数据文件损坏备份重建 | 兜底 |

## 5. 开启方式：仅预设（含推论）

新建会话时选 **"学习模式"预设**（`preset.yml`: `name: 学习模式`）。

**推论（请确认你接受）**：**不存在"中途开启"**。要进入学习模式必须**新建会话**。代价是当前对话的上下文不会带过去——缓解方式是新建后一句话说清"接着学 Java 的对象"。换来的是：永远不会出现半开状态、永远不会在普通会话里看到多余的工具和面板。

## 6. 多树模型与绑定流程

### 6.1 存储：一树一文件

```
outline/
  index.json           # 树的清单：{ id, title, createdAt, lastUsedAt, nodes, done }
  trees/
    java.json          # 一棵树一个文件
    algorithm.json
sessions.json          # { "<sessionId>": { projectId, focusId, cursor, focusSince } }
```

为什么一树一文件：树会长到几百上千节点；一树一文件便于**单独导出/分享/删除**，也避免每次改动重写整个大文件。

### 6.2 进入学习模式后的绑定流程

会话创建 → 首轮，插件注入一条规则 + 工具 `outline_projects()`（列出现有树）：

- **有树** → Agent 用 `ask_user_question` 让你选（"继续 Java / 算法，还是新建？"），你一句选定；
- **无树** → Agent 问"这棵树叫什么"，调 `outline_open({ new: "Java" })` 新建；
- 选定后写 `sessions.json`，之后**这个会话不再问**。

> P0 用"首轮 Agent 问"（零 UI 成本，且复用 DSH 原生提问工具）。P1 再加面板上的图形化选择器——那时候可以直接点，更快。

### 6.3 新会话的默认值

建议：**默认沿用上次使用的那棵树**，首轮只用一句话确认（"继续 Java 那棵？"），而不是每次都让你在两棵树之间做选择——除非你要求。多棵树时提供"切换树"工具 `outline_switch(projectId)`。

### 6.4 树的元信息

`index.json` 里存 `title / createdAt / lastUsedAt / nodes / done`，面板顶部按 `lastUsedAt` 倒序列出，方便你一眼看到"哪棵在活跃"。**树的删除**要二次确认，并且删的是文件（可找回前先备份到 `outline/trash/`）。

## 7. 面板交互

```
[Java ▾]  对象·面向对象思想          [显示已完成 ✓] [⋯]
├ ✔ Java                       3/9
│   ▼ 🎯 对象
│       ├ 继承                   [✓ 学会] [🎯 聚焦]
│       ├ 私有                   [✓ 学会] [🎯 聚焦]
│       └ 面向对象思想  ~~~       [✓ 已完成] [🎯 聚焦]  ← hover 看摘要
│   ▶ 内存管理                    [✓ 学会] [🎯 聚焦]
│   ▶ 语法                       [✓ 学会] [🎯 聚焦]
```

| 操作 | 行为 |
|---|---|
| 点节点标题 | 聚焦（等同 `outline_focus`）；同时触发"离开旧节点"的摘要检查 |
| **[✓ 学会]** | 标记 done + 触发摘要生成；可再点撤销 |
| **[🎯 聚焦]** | 同上 |
| **[显示已完成]** | 纯视图开关 |
| **[⋯]** | 切换树 / 打开数据文件 / 导出 Markdown |
| **hover** | 显示摘要（即"跳过去看学习记录"） |

人手点击与 AI 工具调用**走同一个 `OutlineStore.apply(op)`**，避免"人手改了 AI 不知道 / AI 改了面板不刷新"的撕裂。

## 8. 摘要管道

触发：点 **[✓ 学会]**，或**焦点切换**（旧节点停留期间 ≥4 条消息 或 ≥200 字）。

生成者：**插件用 `ctx.llm` 直接生成**（不进聊天记录、不占 Agent 轮次、不打断你思路）。输入 = 节点路径 + 已有摘要（增量更新）+ 聚焦期间的对话片段（从 `cursor` 起，截断 ~3000 token）；输出 2–4 句：核心结论 / 易错点 / 待续。写入 `node.note / noteAt / noteSource`。

失败 → 标 `pending` 重试（≤3）；同一节点 5 分钟内不重复生成。

## 9. 上下文注入（≤400 token）

```markdown
## 学习模式
树：Java ｜ 焦点：Java > 对象 > 面向对象思想

【当前节点摘要】封装/继承/多态三者关系；多态靠动态绑定；易错：重载≠重写
【子节点摘要】· 继承：…（有摘要才列）  · 私有：…
【未完成（1-2 级）】内存管理、语法、继承
【最近完成】面向对象思想（09-17）、数组（09-16）
```

规则：**有摘要的节点摘要必进**（当前节点 + 子节点）；父链只给标题；未完成截 8 条、最近完成截 3 条；整棵树只在 AI 调 `outline_show` 时给；**未就绪时跳过注入**（§3.3）。

## 10. 工具面

| 工具 | 说明 |
|---|---|
| `outline_projects()` | 列出所有树（首轮绑定用） |
| `outline_open({ projectId \| new: "标题" })` | 选择 / 新建并绑定当前会话 |
| `outline_switch(projectId)` | 切换树 |
| `outline_show(path?, includeDone?)` | 读树（**建树前必须先调，用于查重**） |
| `outline_add(parentPath, items[])` | 追加子项；**幂等**，同名兄弟已存在则跳过并回报 |
| `outline_update(node, rename?/move?/delete?)` | 改名/移位/删除（要求 4 的人审修改方式） |
| `outline_done(node, note?, undo?)` | 与面板 ✓ 按钮同函数 |
| `outline_focus(node)` | 与面板点标题同函数 |

寻址：AI 传**名字路径**（`Java/对象`）→ 插件解析成 id；**歧义时报错要求澄清，不猜**。

## 11. 提示词规则（注入）

1. 首轮：若会话尚未绑定树 → 先 `outline_projects()`，用 `ask_user_question` 让用户选或新建，**绑定后才谈学习内容**。
2. 用户问"X 要学什么 / 包含什么" → 先 `outline_show` 查重 → `outline_add` 只补缺失 → 1-2 句说明，**不要复述整棵树**。
3. 用户说"学完了" → `outline_done`（AI 自己判断的必须先问一句）。
4. 要调整结构 → `outline_update`，**不要重建**已有节点。
5. 不要为了"整齐"重构已有树——粒度不齐由人审。
6. 聊天里只打**增量**。
