# dsh-learning-mode

DSH 的**学习模式**：一棵由 AI 维护、可无限下钻的学习树。

它解决的是一个很具体的痛点：**学习时钻进支线，回头找不到原来的位置**——复习链表时看到"跳表"就去研究跳表，研究完发现要翻很久聊天记录才能回到链表；要复习十个知识点，每学完一个都得回去找下一个。

## 它做什么

- 树是**持久**的：今天学 Java，明天开新会话继续，树还在（可有多棵树）。
- AI **直接往树里写**：你说"我要学 Java，要学什么"，清单就长出来了，不用手抄。
- 无限下钻：对着"对象"再问一句，继承/私有/面向对象思想就挂到它下面。
- **树顺着你的思路长，不按教科书目录**：你由「数组」问到「计算机地址」，它就挂在数组下面——记录的是当时怎么想的。挂节点我来做，你只管问。
- 节点可标完成、可聚焦；**标完成时插件自动写一句摘要**（自己调模型，不进聊天记录）。
- **复习视图**：一个按钮列出所有已完成知识点 + 摘要，复习不用翻聊天记录。
- 每轮对话自动带上"我在哪 + 这层的摘要 + 还没学完什么"。

## 安装状态（示例：作者机器 Linux，DSH_HOME=`/home/<user>/.dsh`）

| 组件 | 位置 |
|---|---|
| 插件包（宿主 + 浏览器半边 + 空 host 插件） | `<本仓库>/dsh-learning-mode/` |
| 学习模式预设 | `$DSH_HOME/.agent-presets/learning-mode/` |
| 插件数据（树 / 会话绑定 / rpc.log） | `$DSH_HOME/learning-mode/` |
| profile 安装 | 已加入 `~/.dsh/profiles/web/package.json`（依赖 + bundles） |
| 依赖链接 | `dsh-learning-mode/node_modules/@deepseek-ai` → 官方 harness 包目录（让预设加载的模块能 `import '@deepseek-ai/dsh-tools'`） |

> 本机用 super-injector 的 `dev_install_package` 做了**热装配**（改 profile + 建 junction + 动态加载），
> 所以不必重启 dsh web；重启后由 `dsh.profile.bundles` 正常装配，两条路径一致。

### 预设是怎么生成的

底预设的选择顺序：你自己的 `router` → 官方 `standard`。
本机 `router` 不存在，所以当前是**基于官方 standard** 组合的（32 行，最后一行是本插件）。

重新生成 / 换底：`node install.mjs standard`（幂等，会先移除旧插件行再追加）。

> ⚠️ 生成时会**逐行校验每个 row 的 name 能否解析**，解析不了直接报错退出，不写出一个会"加载失败"的预设。
> 真实踩过：旧 `router` 里有一行 `deepseek-ai/dsh-workflow-worker-thread` 在本机没装
> （官方 standard 现在用 `dsh-workflow-ptc`），复制过来后整个预设加载失败、会话根本建不起来。

另有一道**真机校验**：`ctx.agentPresets.standingKeyFor('learning-mode')` 会真的把预设组合挂起来，
失败会明确报"哪一行没激活 / 配置非法"。改动预设后值得跑一次（比只看 row 能否解析强得多）。

## 怎么用

1. **刷新 dsh web 页面**（浏览器半边是全局注册的，热装配后刷新即可加载；重启也等价）。
2. **新建会话**，在预设里选 **「学习模式」**。
3. 第一次进入会自动绑定一棵名为「如何使用学习模式」的教程树；顶部下拉框可切换/新建树。
4. 直接对我说：「我要学 Java，要学什么」——清单会直接长到树里。

面板（会话头部「学习树 3/22」按钮点开，浮层 —— 按钮上直接带进度）：

- 点**节点标题** = 聚焦（之后的对话围绕它展开）
- 点 **[学会]** = 标记完成（插件随后自动生成摘要，并自动回到上一层）；再点一次撤销
- 入口按钮=玻璃药丸：`◆ 学习树 3/22`，有新增时多一个红点 `+2`（点开即清）
- 点 **[摘要 ▸]** = 就地展开这个节点的摘要（**默认收着**，见下面的"版面纪律"）
- 点 **[⟳]** = 用模型**重写**该节点的摘要（丢掉旧摘要重来；摘要不对时就按它）
- 点 **[↩]** = **跳回讲这个知识点的那一轮对话**（见下节；只有记到来源的节点才有这个按钮）
- 点 **[▾]** 或父节点上的 **[3/7]** = 收起/展开这一支
- 切到 **[复习]** 页签 = 卡片式列出已完成知识点 + 摘要，点标题可跳回该节点
- 底部 **使用说明** 可展开；顶部下拉框切树、**[＋]** 新建、**[✕]** 或 `Esc` 收起
- 面板窗口可**拖动**（按住头部）、可**拉大小**（右边缘 / 下边缘 / 右下角），并且
  **记住你上次调的样子**（换显示器、缩窗口时会自动钳回屏内）。动过之后头部多一个 **[⟲]** 恢复默认

### 变更提示（v1.3）：树动了，按钮上会告诉你

- 每个节点带 `createdAt`；会话绑定里存一条**水位线** `seenAt`（"上次看过这棵树的时间"）
- 节点比水位线新 = **新增** → 会话头部按钮上出现红点 `+3`，树里该节点标 `NEW`
  （并**强制展开它的祖先分支**，否则藏在折叠里看不见；顶部还有一行"上次看过后新增 3 个知识点"）
- **点开面板**：红点立刻消失（乐观更新 + 落盘 `op=seen`），但树里的 `NEW` 会留着——你正要看
- **关掉再打开**：`NEW` 自然消失（标记是拿 `createdAt` 和水位线**算**出来的，不是存出来的）
- **删除不产生标记**（只认 `createdAt`，用户明确"删除就不管了"）
- 换树 / 新会话首次绑定都会把水位线推到当下，所以老树不会一上来满屏 `NEW`

### 跳回「讲它的那次对话」（v1.4）：树行上的 [↩]

树上每个节点都记着**它是在哪轮对话里被讲到的**（`origins`，最多 3 条，最新在前，按 `会话+轮号` 去重）：

```json
[{ "sid": "session-…", "turn": 12, "seq": 345,
   "time": "2026-09-18T05:51:12.147Z", "why": "capture" }]
```

- 有来源的节点，树行上会多一个淡色 **[↩]**；点一下 = 切到那次会话（若不在当前会话）→
  滚到那一轮 → 那一行**闪一下高亮**（1.8 秒后自动消失，不留痕迹）。
- 来源写在**四个**时刻：`outline_capture`（AI 新建知识点）、标 **[学会]**、**[⟳]** 重写摘要，
  以及 —— **每轮对话结束时"当前聚焦的那个节点"**。
  最后这条就是「对话2 聚焦了 a → a 的跳转改为对话2」的实现方式：
  它必须记在"这一轮**结束**"而不是"聚焦那一刻"，因为面板点选发生在提问**之前**，
  那一刻日志里最后一个轮次还是上一轮（详见开发说明第九/十轮）。
  一轮最多记一个节点，所以纯浏览点击不会污染一片；下次真正讨论会覆盖旧的。
- 坐标是 **(会话, 轮号, 事件号)**，**不是消息 id**：外壳的会话流按**轮**分行（每行带 `data-chat-turn`），
  更早的分页用官方 `loadThrough(seq)` 补页 —— 这是能"跳过去"的两个抓手；而 messageId 在聊天 DOM 里
  没有任何锚点。所以定位粒度就是"轮"，跟外壳自己的 TurnNavigator 同粒度。
- **失败不静默**：目标会话被删/归档 → 面板里明说"那次对话已经不在了"；找不到那一轮 → 也给一句提示。
  每一步都往 `rpc.log` 记 `jump …` / `env …`，事后可查（**前端 console 不落盘**，见开发说明的坑 15）。
- **老节点回填**：`npm run backfill:origins`（默认 dry-run 出报告，`--write` 才写盘并自动备份树文件）。
  它扫会话日志里的 `outline_capture` / `outline_add` 调用，按标题把坐标对回节点 ——
  本机实测 150 个节点回填了 135 个（剩下的 15 个就是内置教程树，本来就没有对话来源）。

### 玻璃质感与"液态"的边界

面板和入口按钮是**磨砂玻璃**：`color-mix(in srgb, var(--dsw-alias-bg-overlay) 74%, transparent)`
+ `backdrop-filter: blur(16px) saturate(1.7)` + 内高光 + 外阴影，
`@supports not (backdrop-filter)` 时退回不透明底。这个配方**跟 DSH 自己的浮层一致**
（打包 CSS 里是 `color-mix(...bg-base 72%, transparent)` + `blur(6px)`）。

> ⚠️ 真·"液态折射"（背景被透镜扭曲）在 Web 里做不到：`backdrop-filter` 只接受
> `blur/saturate/...` 这些滤镜函数，**不接受 `url(#svgFilter)`**，所以 `feDisplacementMap`
> 那套折射实现不了。现在做的是 iOS 意义上的 material：磨砂 + 高光边缘 + 悬停流光。

### 面板的版面纪律（改 UI 前先读）

这个面板是**导航器**，不是阅读器。三条硬约束，都是实拍反馈换来的：

1. **树永远一行一个节点**。摘要**不默认展开**——旧版把 4-5 行摘要直接铺在树里，
   整棵树被顶散、看不到结构（实拍："总结的占空显示不合理"）。摘要挂在 `摘要 ▸` 后面，点了才展开。
2. **"我在哪"必须一眼可见**：聚焦行 = `▶` 标记 + 左侧 brand 色强调条 + 淡色底。
3. **"还剩多少"必须一眼可见**：顶部进度条 + `3/22` 数字 + 每个父节点的 `3/7` 角标
   + 会话头部按钮上直接显示 `学习树 3/22`。

配色一律用主题 CSS 变量（portal 到 body 也必须跟主题走）；行内 `⟳` 平时压低透明度，
悬停才亮（按钮满屏会吵）。这些视觉规则由 `test/client.mjs` 断言守着（默认不展开、
有摘要给按钮、聚焦有 ▶、父节点有进度角标）。

## 零侵入（这是本插件最重要的设计约束）

| 层 | 隔离方式 |
|---|---|
| 工具（`outline_*`） | 只写进「学习模式」预设，**其它会话的工具表里根本没有它们** |
| 提示词规则 / 每轮状态 | 随 agent 作用域派发，只对学习模式会话生效 |
| host 平面 | 只挂一个**空插件** `lib/client-host.js`（什么都不注册），唯一作用是让浏览器半边被 client-modules 扫描到 |

> ⚠️ **bundle patch 里的行名必须是包根**（`dsh-learning-mode`），不能写子路径。
> `dsh-client-modules` 用 `exactPackageSpecifier()` 定位包清单：**含 `/` 的说明符一律返回 undefined**，
> 该行会被判为「不是客户端包」并**整个跳过**——表现为前端毫无反应、且没有任何报错。
> 真实踩过一次：写成 `dsh-learning-mode/client-host` 就静默失效了。
> 因此 package.json 的 main 与 exports 根导出指向无害的 `lib/client-host.js`，真插件走 `./host` 子路径 + 预设的 `file:` 说明符。
| 浏览器面板 | 组件全局注册，但宿主判定非学习会话时 **render null**——代码常驻、行为零侵入 |
| 异常 | 全链路 try/catch：注入失败静默跳过、数据损坏自动备份重建，绝不影响会话主流程 |

> 为什么 host 平面不能直接挂 `lib/index.js`：那会让 7 个工具在**所有**会话里注册。所以拆成两半——
> `lib/client-host.js`（host 平面，空）负责"被扫到"，`lib/index.js`（agent 平面，预设用 `file:` 说明符引入）负责全部真实功能。

## 本版（v1.1）做了什么、还没做什么

**已实现并自检通过**

- 多棵学习树（切换 / 新建）、无限层级、完成标记、聚焦
- 9 个模型可调工具：`outline_projects / open / show / add / update / done / focus / review / capture`
- 每轮自动注入：当前焦点 + 当前节点摘要 + 子节点摘要 + 未完成 + 最近完成（带日期）
  - ⚠️ 实现要点（踩过一次致命坑，改这块前先读 `继续开发说明.md` 坑 13）：注入走
    `ctx.systemPrompt.context({ text: (context) => ... })`，**会话必须从框架传进来的
    `context.agent` 取**（官方 `dsh-sandbox-policy` / `dsh-user-approval` 同款写法）。
    绝不能写 `ctx.agents`——它不在 `inject` 里，真实 Cordis 代理会抛
    `cannot get property "agents" without inject`；也不能把异常吞成空串，那等于"注入静默失效"。
    现在异常/空注入会按原因各记一次 `rpc.log`（`inject diag: ...`），
    单测的假 ctx 是 **Proxy**（未声明属性一律抛错），复刻真实代理的严格性。
- 首轮绑定上次使用的树；首次使用自动建教程树
- 浏览器浮层面板（树视图 + 复习视图）+ 使用说明
- 面板 ↔ 宿主 RPC（`POST /api/learning-mode/rpc`：state / review / open / create / focus / done / note / **seen**）
- **摘要自动生成**（P4）：标"学会"或切换焦点时，插件用 `ctx.llm` 直接生成 2-4 句摘要写进节点
- **复习视图**：面板 [复习] 页签 + `outline_review` 工具，按完成时间倒序列出已完成 + 摘要
- **学习会话自带减负**：不挂开发向工具（`dev_*` 共 18 个，实测占工具 schema 5567 字符/约 1.4k token）
  ——`agent/created` 时在该 agent 作用域 `tools.restrict({deny})`，全局注册不受影响；
  super-injector 的开发向引导段也在学习会话里静音（注入器侧 `mutePresets: ['learning-mode']`）
- **无感整理**（`outline_capture`）：一轮最多一次静默挂载，挂在当前焦点下；同名节点自动复用。
  ⚠️ **不搬焦点**（默认）：焦点是"用户在看哪"，只有用户能改变它。真机上曾因为整理顺手搬焦点，
  导致介绍父节点时顺带挂的子节点抢走位置，下一轮模型就继续讲那个子节点（见 `继续开发说明.md` 第六轮）

**还没做（按方案次序）**

- 原生右侧面板页签（现在是 `shell.overlay` 浮层面板；改成 `sidebar.right.pane.tab` 要接右侧 tab 类型注册表 `ctx.sidebarRightTabs`）
- 间隔重复（SM-2）提醒、导出 Markdown、树删除（目前只能删节点）

## 聚焦 = 下钻，✓ = 回到上一层

用户确认的交互模型（不需要焦点栈）：

| 行为 | 结果 |
|---|---|
| 点任意节点 / AI 调 `outline_focus` | 聚焦它（下钻或横向切换都允许） |
| AI 调 `outline_capture`（整理） | 新节点挂到当前焦点下，**焦点不动**——焦点代表"用户在看哪"，只有用户能改变它 |
| AI 调 `outline_capture({focus:true})` / `outline_focus` | 焦点移过去。**只在"用户这一问的主题就是它"**（或用户点名了已有节点）时才这么做 |
| **点 [✓ 学会]（该节点正是当前焦点）** | 生成摘要，**然后焦点自动上移到父节点** —— 这就是"钻进去学完，原地返回" |
| 顶层节点被标完成 | 焦点不动（没有父可回） |
| 再点一次撤销完成 | 焦点不动（不会又跳下去） |
| 在非当前焦点节点上点 ✓（如复习视图里） | 只完成，焦点不动 |
| 没学完就横向切走 | 焦点跟着走；想回去**在树里点那个节点**（树本身就是地图，不做历史栈） |

## 开场：第一句话就让你选树（只问一次）

新会话第一轮，注入块会带两行（**只在"还没用过树"时出现**，确认过就消失，不占长期上下文）：

```
【现有学习树】数据结构（44 节点·09-18）、Java（31 节点·09-18）、如何使用学习模式（15 节点·09-18）
【开场·只做一次】用户第一句若与上述某棵树相关 → 用 ask_user_question 出选项：
   第一个＝你推荐的那棵树（(Recommended)），其后是其它相关的树，再给「新建一棵（名字建议：X）」；用户也可以自己填。
   选完调 outline_open，然后正常回答，不要再问第二次。
   若与任何老树都无关 → 同样用选项问：第一个＝你建议的树名，第二个＝让用户自己填名字。
```

配套的通用规则：**与学习内容无关的确认（选树/命名/是否新建）一律用 `ask_user_question` 结构化选项**，
不用对话来回问——这是用户的明确要求（省上下文、不分心）。
`autoBind`（静默沿用上次的树）保留为兜底，模型忘了问也不会坏。

## 发散优先：树记录"当时的思路"，不是知识体系

这是本插件的核心产品决策，写在规则段（`lib/index.js` 的 `RULES`）里，由 AI 在每轮解答后**静默**执行：

| 场景 | 做法 |
|---|---|
| 你问「数组和链表的区别」，接着问「什么是内存地址」 | 「内存地址」挂在**数组**下面（即使它是前置知识），**你的位置不动**（还在「数组」） |
| 你下一句问「那内存地址呢」 | 这时才 `outline_focus` 到「内存地址」，之后的追问挂到它下面 |
| AI 在回答里顺带提到的子概念 | 挂成子节点 + 一两句带过，**不搬焦点**、也不替你展开成完整一节（想深入你自己点进去） |
| 同名知识点再次出现 | 全树查重后**复用**已有节点，不重复建、也不擅自搬家 |
| 聊天里 | **一句话都不提**（不写"已添加 X"、不复述树、不问要不要记） |

**上下文代价**：工具回执只有 `captured: <路径>` / `exists: <路径>`，不往上下文灌树。

> ⚠️ 已知风险：capture 是**提示词驱动**的——模型漏调 = 静默失败。
> 规则段 + 注入块末尾的行动提示（"答完把新知识点 outline_capture 到当前焦点下"）是两道提醒；
> 若实测仍漏，下一步是插件侧兜底：监听 `agent/turn-stopping`，本轮没有 capture 就用一次轻量
> LLM 调用抽取知识点（代价：每轮多一次模型调用）。取数判据：`rpc.log` 里的 `op=capture`。

## 摘要管道（v1.1 新增，方案 §8）

| 项 | 做法 |
|---|---|
| 触发 | **只有两条**：① 点 [✓ 学会]（或 AI 调 `outline_done`，且没带人工摘要）；② 面板 [⟳] 强制重写。**焦点切换不再生成摘要**（用户确认：钻进概念时不该顺手总结上一节，也省掉每次切换一次 10~27 秒的模型调用） |
| 生成者 | 插件自己调 `ctx.llm.stream()`，**不进聊天记录、不占 Agent 轮次、不打断思路** |
| 原料窗口 | `session.snapshotEvents()` 里从**该节点最后一次被聚焦的时间**（`lastEnteredAt`）起的真人/模型发言。**三级兜底**，任何一级都比"整场会话"强：① 该节点自己被聚焦过 → 用它的时间；② 它自己没进过（AI 在父节点里一口气列了 6 个前置概念，用户直接给其中一个点 ✓）→ 退到**最近进过的祖先**的时间；③ 祖先也没进过 → 用节点 `createdAt`。`windowStart` 返回 0（整场会话）只应发生在"什么记录都没有"的情况下 |
| 原料收窄 | 送进模型前先按**节点标题**切小节：命中的那条 AI 消息只保留标题命中它的那一节（`## 1. xxx` 或 `1. xxx` 都认），没命中的整条丢掉。真机 bug：AI 用 `## 1./## 2.…` 一节讲一个前置概念、树里存成 6 个子节点，不收窄时模型会去总结"共同的上一层主题"（实测给「rollout 的交互税」写出了整篇论文的摘要）。收窄后不足 120 字则不收窄（宁可多给，不要饿着模型） |
| 边界信息 | 提示词里点名**本次要总结的知识点 + 它在树里的位置 + 同层其它知识点（≤10 条，明确"不属于本次总结"）**，并说明"原料里很可能同时讲了别的知识点甚至整篇论文，那些一个字都不要写进来" |
| 门槛 | ≥4 条消息 或 ≥200 字；同一节点 5 分钟内不重复生成 |
| 输出 | 2-4 句：核心结论 / 易错点 / 待续；**点 ✓ 时**已有摘要做**增量合并**（同一知识点以后再学时新结论叠加在旧结论上），**面板 [⟳] 是 fresh 重写**（不带旧摘要——按它通常就是因为这条摘要不对，合并会把错的留着） |
| 失败 | 标 `noteState: failed` + 累计 tries（≤3），面板显示"没生成出来"（hover 看具体原因）并可手动重试；**绝不阻塞或抛给主流程** |
| 模型路由 | 优先用该会话上一次请求实际用的 provider/model，回退全局默认模型 |
| 思考 | **显式 `reasoningEffort: "off"`** —— 摘要这种小任务开推理会把 token 预算烧光（真机实测：预算耗尽、文本块为空、`finish = max-tokens`），官方 session-title 同样关思考 |
| 预算 | `maxTokens: 1200` 是**含思考**的总预算；被 max-tokens 截断时，有产出就收下，一个字都没有才报错 |
| 容错 | 模型不认 `reasoningEffort` 时报错关键词命中 → 自动去掉该字段重试一次（换模型不会把摘要废掉） |

节点上的摘要状态字段：`noteState` = `running`（生成中）/ `done` / `skipped`（内容太少或模型答"无内容"）/ `failed`
（失败原因存 `noteError`，一路透传到面板 hover 提示，方便当场定位）。

> 🔁 **面板必须"自己回到节奏"**：插件是在 `agent/created` 之后才把会话标成学习模式的，
> 面板往往比它早到。旧版拿到 `enabled:false` 就停轮询 → 学习树按钮永远不出现，
> **必须切一次聊天框**才加载（实拍反馈）。现在未启用时 0.8s 快轮询（前 ~10s，之后 5s）、
> 启用后 3s 常态轮询，404（会话还没注册）也只当"还没到时候"退避重试。

## 节点寻址：标题里可以带 `/`

真实树里就有 `插入/删除`、`时间/空间复杂度对照`、`Java：int[] / ArrayList 的取舍` 这类标题。两条路都覆盖：

| 入口 | 做法 |
|---|---|
| 面板点选（聚焦/完成/重写摘要） | 一律送 **node id**（`resolvePath` 把 id 解析成规范路径），彻底绕开标题歧义 |
| AI 调工具（`outline_done` 等） | 传标题路径；`findNode` 用**最长段优先 + 回溯**解析 —— `链表/插入/删除` 会正确落到 `链表 > "插入/删除"`，而不是去找 `插入 > 删除` |

> 这是真机踩出来的：旧 `findNode` 直接 `split('/')` 逐段匹配，含斜杠的节点**永远无法寻址**，
> 症状是"点聚焦后下一轮像没聚焦"——焦点解析不出节点 → 注入块里【当前节点摘要】整段丢失。

## 上下文预算（注入块不随树膨胀）

每轮注入的动态状态段有**硬上限 1200 字符**（≈400 token，`CONTEXT_MAX_CHARS`），超预算时按优先级逐级降级：

```
子节点摘要 6→3→1→0 条 ｜ 未完成 8→4→2→0 条 ｜ 最近完成 3→2→1→0 条
→ 先丢"复习提示/行动提示" → 单条摘要裁到 120 字符 → 最后硬切
```

**【这一层还没学完】只给同一层**（聚焦节点的子节点 + 兄弟）——绝不给全树广度优先的清单，
否则用户说"介绍"这种没有宾语的话时，模型会从无关知识点里挑一个来答（真机踩过）。

规则：**有摘要的节点摘要必进**（当前节点 + 子节点）；父链只给标题；
**整棵树只在 AI 调 `outline_show` 时给**，绝不每轮注入；未就绪/未绑定时**一行都不注入**。

> 🎨 **面板配色必须用主题变量**：面板是 portal 到 `document.body` 的浮层，早先硬编码
> `rgba(40,40,44,0.96)` + `color: inherit`，浅色主题下就成了"深底深字"。现在统一用
> `--dsw-alias-bg-overlay / label-primary / label-secondary / border-l1 / state-success-primary`
> 等 token（`dsh-client-ui-theme` 注入在 `:root`，portal 子节点能继承），并各带兜底值。

> ⚠️ `lib/summary.js` **刻意不在顶层 `import '@deepseek-ai/dsh-llm'`**：import 是挂载期解析，
> 该包一旦改名/缺失，整个「学习模式」预设就加载失败（= 学习模式开不了会话），代价完全不对称。
> 改为首次真正生成摘要时动态 import，拿不到就用内置最小实现兜底。

## 多语言（i18n）

插件的**全部文案跟随 DSH 当前语言**（内置 `zh` / `en`）：面板 UI、每轮注入给模型的指令、
九个工具的描述与回执、摘要提示词、教程树种子，语言改了下一次调用就生效。

约定是 **「中文原文就是字典的 key」**：代码里 `t('尚未绑定学习树')`，英文表
`EN = { '尚未绑定学习树': 'No learning tree bound yet' }`，中文表由 EN 的 key 恒等派生。
好处是**漏翻必被测试抓住**，且中文路径零改动（字典缺 key 时中文界面取到的就是 key 本身）。

两边各有一份字典，因为 `lib/client.js` 不是 ESM（是 `window.__ModuleLoader__.load({factory})`
的闭包模块，无法 `import './i18n.js'`）：宿主侧在 `lib/i18n.js`（`t`），浏览器侧内嵌在
`lib/client.js`（`T`，⚠️ 大写，避免被文件里的局部 `t` 遮蔽）。

已知限制两条：工具 `description` 由 `defineTool()` 在挂载时定型，**语言变更要等进程重启**
（注入块/回执/摘要提示词是调用时取值，立刻跟着变）；`preset.yml` 只有纯文本
`name`/`description`，没有 i18n 字段，所以预设显示名不随语言变。

细节与踩坑（含 `t` 被局部变量遮蔽的地雷、兜底翻译必须插值）见 `../继续开发说明.md` §9 与坑 19。

## 自检

```bash
node test/smoke.mjs                # 数据层：建树 / 幂等 / 改结构 / 摘要字段 / 复习视图 / 容错
node test/mount.mjs                # 宿主半边集成：挂载 → 绑定 → 8 个工具 → 摘要管道 → 注入 → 面板 RPC
node test/summary.mjs              # 摘要管道：门槛 / 生成 / 落盘 / 失败重试 / 冷却 / 窗口过滤
node test/client.mjs               # 浏览器半边：注册座位 / 未开启会话 render null / 树视图 / 复习视图
node test/i18n.mjs                 # 多语言守卫：key 齐不齐 / 英文值是不是真英文 / 占位符对齐 / 无重复 key
node test/probe.mjs                # 最小挂载探针：确认 apply() 不抛错、8 个工具注册到位
node scripts/validate-preset.mjs   # 预设里每个 row 的 name 是否可解析（加载失败的第一道防线）
```

`mount.mjs` 是关键：它模拟 cordis 上下文真实调用 `apply()` 和每个工具的 `execute()`——
因为**挂载期抛错会让整个「学习模式」预设无法创建会话**，这一步必须先过。
`npm run verify:live [sessionId前缀]` 是**真机核查**（不是单测）：解真实会话日志，核对每轮注入是否
真的进了运行时快照、学习会话有没有混进 super-injector 引导、`dev_*` 工具是否已屏蔽——重启 dsh web
后跑一次就知道生效没有（本插件两次"单测全绿、真机全死"的教训换来的工具）。

`summary.mjs` 用假 session + 假 llm 覆盖摘要管道的全部分支（含"模型抛错不能影响主流程"）。
`client.mjs` 用元素记录型迷你 React 把面板组件真渲染一遍（普通会话 render null、树视图、复习视图各分支），
面板改动的回归靠它兜底——真机可见性仍需人眼确认。
